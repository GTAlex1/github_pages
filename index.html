    ¿Qué es GitHub?

    Git y GitHub se confunden, pero no son lo mismo.

    Git

    Programa que se instala en tu ordenador. Guarda el historial de cada cambio de tus archivos. Funciona sin internet.

    GitHub

    Servicio web que aloja repositorios Git y añade herramientas para colaborar: revisiones, incidencias, automatización y publicación.

    • Guardar versiones y volver atrás si algo se rompe
    • Trabajar varias personas en el mismo proyecto
    • Mostrar tu trabajo como portfolio público

    Conceptos básicos

    Repositorio

    La carpeta del proyecto con todo su historial.

    Commit

    Una foto del proyecto en un momento, con un mensaje que la explica.

    Branch

    Una rama paralela para probar cambios sin tocar la principal.

    Merge

    Unir los cambios de una rama en otra.

    Primeros pasos

    1. Crea tu cuenta (con 2FA) e instala Git
    2. Fork del repositorio del taller
    3. Cópialo a tu equipo con git clone
    4. Crea una rama y tu página: switch, add, commit
    5. push, abre la Pull Request y pull

    Repositorio del taller: github.com/gtalex1/taller-github

    5 / 14

    Flujo de trabajo colaborativo

    1. Fork: copia el repositorio de otra persona a tu cuenta
    2. Branch: crea una rama y haz tus cambios
    3. Pull Request: propón que tus cambios se unan al proyecto
    4. Code review: el equipo comenta, pide ajustes y aprueba
    5. Merge: los cambios entran en la rama principal
    Issue #12 abierto

    Los issues son las tareas e ideas del proyecto. Si la PR incluye «Closes #12», el issue se cierra solo al hacer merge.

    GitHub Actions

    Automatiza tareas cada vez que ocurre algo en el repositorio: probar el código (CI) y desplegarlo (CD).

    # .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test
    git pushTestsDeploy
    ⚪ Sin desplegar

    Cada push lanza los tests. Si fallan, lo ves en la PR antes de unir nada.

    Seguridad

    Dependabot

    Avisa de librerías vulnerables y abre PRs para actualizarlas.

    Secretos

    Las claves van en Secrets, nunca dentro del código. GitHub detecta las que se cuelan.

    Permisos

    Roles de lectura, escritura y admin. Ramas protegidas que exigen revisión.

    2FA

    Segundo factor en tu cuenta. Es obligatorio para quien contribuye código.

    Copilot y extras

    GitHub Copilot

    Asistente de IA que sugiere código y responde dudas dentro del editor.

    Codespaces

    Un entorno de desarrollo completo en el navegador, sin instalar nada.

    Discussions

    Foro del repositorio para preguntas y ideas que no son issues.

    Tab ⇥

    Cuando aparezca la sugerencia en gris, pulsa Tab para aceptarla.

    Buenas prácticas

    Salud del repositorio

    Un proyecto cuidado se entiende sin preguntar.
    README.md
    Qué es el proyecto y cómo usarlo
    .gitignore
    Archivos que Git debe ignorar (claves, node_modules…)
    LICENSE
    Qué pueden hacer otros con tu código (MIT, GPL…)
    Commits claros
    Cada mensaje dice qué cambió y por qué

    Conclusiones

    • Git guarda el historial; GitHub lo hace colaborativo
    • Ramas y Pull Requests permiten trabajar en equipo sin pisarse
    • Actions, Pages y Dependabot automatizan lo repetitivo
    • Un buen README y commits claros hacen el proyecto entendible
